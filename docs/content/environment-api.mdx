## Service

The service lifecycle is:

`ListTasks → CreateEnvironment → Initialize (inside CreateEnvironment) → Execute* → Evaluate → Teardown`.

`CreateEnvironment` does not return until the guest has validated the opaque
catalog payload and generated initial messages and tool schemas.

## Requests

`EvaluateRequest` carries `env_id`, an optional `final_message_json`, and a
`termination_reason`. This allows single-turn environments to grade a plain
assistant response. Guest initialization receives `env_id` and opaque
`task_payload_json` and returns `initial_messages_json` and `tools_json`.

```protobuf
message InitializeRequest {
  string env_id = 1;
  string task_payload_json = 2;
}

message ExecuteRequest {
  string env_id = 1;
  string tool_name = 2;
  string arguments_json = 3;
}

message EvaluateRequest {
  string env_id = 1;
  string final_message_json = 2;
  string termination_reason = 3;
}
```

## Responses

Responses include stdout, stderr, exit status, and structured error details.

## Errors

Errors distinguish user-command failures from manager, transport, and VM lifecycle failures.
